# 项目总览（Overview）

## 1. 目标
本项目用于集中展示 Yorushika 相关歌曲内容，提供可视化浏览与筛选能力，并支持本地收藏。

## 2. 当前功能边界
- 包含：
  - Yorushika 官方艺人目录中的 22 部音乐发行、111 首独立曲目与 124 个曲序位置。
  - 首页每日推荐、聆听路径与代表作品。
  - 作品集按年份和发行类型筛选，并按官方曲序展示。
  - 单曲详情、同作品前后曲目、官方来源与已核对的第三方影像入口。
  - 每日推荐（按日期种子随机）。
  - 搜索筛选（关键词、年份、编辑顺序/年份/标题排序）。
  - Song Stories（原创短评、真实专辑信息和官方来源）。
  - 私人 HLS Radio（24 首白名单曲目、当前曲目与近似进度）。
  - 关于页展示（策展缘起、资料原则、收录边界、建站阶段与本地收藏）。
  - 收藏系统（浏览器本地存储）。
- 不包含：
  - 评论/留言能力（已移除）。
  - 头像上传能力（已关闭）。
  - 公开音乐分发、下载和歌词全文转载。
  - 自动抓取第三方榜单或自动导入未知音频。

## 3. 页面与路由
- `/`：首页（每日推荐 + 聆听路径 + 作品入口）。
- `/discography`：按作品、年份和发行类型浏览完整曲序。
- `/songs/<slug>`：单曲资料、个人整理、来源与同作品前后曲目。
- `/search`：搜索与筛选页。
- `/lyrics`：Song Stories。
- `/radio`：白名单私人 Radio。
- `/about`：本站策展说明、收录边界与浏览器本地收藏。
- `/robots.txt`：禁止搜索引擎抓取。

## 4. 代码结构
- `app.py`：应用工厂、安全响应头、蓝图与迁移注册。
- `wsgi.py`：Gunicorn 入口。
- `routes/main.py`：页面路由与查询。
- `models.py`：曲目、发行作品与作品曲序关联模型。
- `config.py`：环境变量读取、数据库连接与安全校验。
- `catalog_data.py`：人工校对的作品元数据。
- `catalog_service.py`：非破坏性目录同步。
- `migrations/`：数据库结构迁移。
- `tests/`：目录、页面、安全头、Radio 与迁移测试。
- `templates/`：Jinja2 模板。
- `static/`：样式、图片、前端脚本。
- `scripts/generate_radio_schedule.py`：Radio 白名单与时间表生成。

## 5. 关键技术说明
- `Blueprint`：Flask 的路由模块化机制。
  - 中文解释：把路由按业务拆分，便于维护。
- `ORM`：对象关系映射。
  - 中文解释：用 Python 类操作数据库，减少手写 SQL。
- `localStorage`：浏览器本地存储。
  - 中文解释：收藏数据保存在用户浏览器，不走服务端。

## 6. 当前边界
- 111 首独立曲目都可追溯到已核对的官方发行页；124 个曲序位置保留同曲跨作品收录关系。
- 22 部作品均具备完整策展档案；官方公开信息和本站个人聆听笔记分区展示，个人路径不冒充官方章节划分。
- 只有 24 首曲目具备人工核对的 Bilibili 影像入口；核对仅证明页面可达且标题与曲目相符，不证明官方授权或长期可用。其余曲目只保留官方作品来源。
- 当前目录以 `https://yorushika.com/discography/artist/2/` 中的音乐发行为范围，不含 Live 影像制品、书简型小说及 suis / n-buna 个人作品，也不承诺永远等同于后续新增发行。
- Radio 进度来自服务端播单时间线，受 HLS 缓冲影响可能有数秒误差。
- 音频与数据库不进入 Git；Git 不是完整服务器备份。
