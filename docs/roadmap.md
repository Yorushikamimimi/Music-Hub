# 迭代路线图（Roadmap）

## 已上线基线
1. 静态资源减重与缓存。
2. 真实作品目录、Song Stories 和官方来源。
3. Radio 私密边界、24 首白名单与非自动播放。
4. 移动导航和基础无障碍，不改整体视觉语言。
5. 可回滚数据库迁移与确定性目录同步。
6. 移除伪 HOT / 评分。
7. Web / Radio 非 root 目标配置。
8. 哈希依赖锁、迁移测试、页面测试和 Radio 时间表测试。

## 当前可靠性阶段（已于 2026-07-28 上线）
1. 5 分钟一次的 Web、数据库和 Radio 全链路健康检查。
2. 健康检查或备份失败时写入独立 journal 和最后失败状态。
3. 每日压缩 MySQL 备份、SHA-256 校验与 14 份精确保留。
4. 部署前完整代码快照、5 份保留和可识别部署版本。
5. 默认只预演的回滚命令，以及隔离 MySQL 容器恢复演练。

## 本阶段上线验收
1. 新 systemd unit 已通过服务器端校验并安装。
2. 真实健康检查已通过，5 分钟 timer 已启用。
3. 真实数据库备份已在临时隔离容器中恢复并查到核心表。
4. 回滚只运行 plan，未覆盖当前线上文件，也未回滚数据库。
5. 每日备份 timer 已启用并确认下次触发窗口。
6. 故障记录链路已通过无业务影响的瞬时失败自测。

## 仍然明确不覆盖
- 同盘备份不能应对整机或系统盘损坏，仍需要单独的异地备份方案。
- 当前故障记录只落本机 journal 和状态文件，不会主动发送邮件或消息。
- 自动化浏览器验证了 HLS 资源和元数据，但 Chromium 不提供原生 HLS
  播放能力，可听性仍需在支持 HLS 的真实用户浏览器中验收。

## 第二阶段（2026-07-28 已上线）
1. 统一为“夜鹿集 / YORUSHIKA ARCHIVE”视觉语言与站点命名。
2. 重做首页信息架构、作品封面比例与聆听路径。
3. 建立 8 张作品、63 首曲目的作品集和单曲详情页。
4. 恢复 20 首人工核验的 Bilibili MV / 影像入口。
5. 为桌面与手机端补齐筛选、曲序、前后曲目和无横向溢出布局。

## 第三阶段（2026-07-28 已完成本地验收）
1. 按 8 张发行作品的官方完整页面重新核对，不再以歌词页代替完整曲序。
2. 从 63 首补齐到 89 首，纳入器乐过场和《幻燈》的十个“夜”章节。
3. 保存精确发行日期、作品内曲序和来源复核日期，并提供可回滚迁移。
4. 人工核验影像入口从 20 首增至 24 首，不采用无法确认的翻奏或搬运链接。
5. 修复同作品共用封面时目录同步可能复用错误记录的问题。
6. 54 项自动化测试、桌面端和 390px 手机端浏览器验收均通过。

## 下一版
1. 把 About 从通用开发者模板改为本站策展说明。
2. 补充专辑背景、时期脉络和可标注来源的个人听歌笔记。
3. 继续核验其余曲目的官方影像或可靠平台入口，不用搜索结果自动填充。
4. 决定是否把 8 张作品之外的后续发行物、数字单曲纳入下一批目录。
5. 再决定是否增加服务端收藏、后台管理或独立 API。

## 非目标（当前阶段不做）
- 评论系统恢复。
- 用户上传图片恢复。
- 公开 Radio、音频下载和完整歌词转载。
- 未经来源核验自动生成作品事实、歌词或影像链接。
